# 나만의 오목 헬퍼 (OMOK-HELPER)

스마트폰 화면에 보이는 오목판을 **실시간으로 읽어서**, 다음에 둘 좋은 자리를 게임 화면 위에 고리로 표시해 주는 안드로이드 앱입니다.
AI 생각 시간은 **0.5초 · 1.5초 · 3초 · 4초 · 5초** 중에서 고를 수 있습니다.

## 설치

1. 이 저장소의 **Releases → `latest`** 에서 `OmokHelper.apk` 를 휴대폰으로 받습니다.
   (또는 **Actions** 탭 → 최근 빌드 → `OmokHelper-apk` 를 받아 압축 풀기)
2. APK를 열어 설치합니다. "출처를 알 수 없는 앱" 설치를 허용해야 할 수 있습니다.

안드로이드 8.0 (API 26) 이상에서 동작합니다.

## 사용 방법

1. 앱에서 **판 크기(15/19줄)**, **규칙(자유룰/렌주룰)** 을 게임과 같게 고르고 **AI 생각 시간**을 정합니다.
2. **다른 앱 위에 표시** 권한을 허용합니다.
3. **[화면 감지 시작]** → 화면 녹화를 허용합니다. (전체 화면 공유)
4. 오목 게임을 열고 떠 있는 패널의 **[판 맞추기]** 를 누릅니다.
5. 분홍 십자 두 개를 바둑판의 **맨 왼쪽 위 교차점**, **맨 오른쪽 아래 교차점**에 맞춥니다.
   파란 격자 미리보기가 판의 선과 겹치면 맞은 것입니다. ◀▲▼▶ 로 1픽셀씩 조정할 수 있어요. **[저장]**.
6. 판이 바뀔 때마다 추천 자리에 고리가 생깁니다. **빨강 1순위 · 주황 2순위 · 파랑 3순위 이하**
   패널에는 좌표와 이유(예: `H8  4-3 공격 (필승)`), 예상 수순, 탐색 깊이가 나옵니다.

> 패널도 화면 캡처에 찍히기 때문에, 패널이 바둑판을 가리면 그 부분의 돌을 읽지 못합니다.
> 제목(⠿)을 끌어서 판 밖으로 옮겨 두세요. 가리고 있으면 패널에 경고가 뜹니다.

### 게임 중에 바꿀 수 있는 것 (패널 칩)

| 칩 | 누를 때마다 |
|---|---|
| `나: 자동` | 자동 → 흑 → 백. 흑/백이면 내 차례일 때만 추천하고, 상대 차례엔 "기다리는 중" |
| `⏱ 1.5초` | 0.5초 → 1.5초 → 3초 → **4초** → **5초** → 0.5초 … |
| `–` | 패널 접기/펴기 |

### 첫 화면 설정

| 항목 | 선택 |
|---|---|
| 판 크기 | 15줄 / 19줄 |
| 규칙 | 자유룰 / 렌주룰 (흑 3-3·4-4·장목 금지) |
| AI 생각 시간 | 0.5초 / 1.5초 / 3초 / 4초 / 5초 |
| 추천 개수 | 1개 / 3개 / 5개 |
| 내 돌 | 자동 / 흑 / 백 |

## 동작 원리

```
화면 캡처 ──▶ 바둑판 읽기 ──▶ 수 분석 ──▶ 오버레이 표시
(0.5초마다)   (밝기·채도)     (탐색 AI)     (추천 고리)
```

### 1. 화면 캡처 — `CaptureService.java`
`MediaProjection`으로 화면을 0.5초마다 받아 옵니다(짧은 변 720px로 축소).
**같은 판이 두 번 연속 읽혀야** 확정해서, 돌이 놓이는 애니메이션 중간 화면은 무시합니다.

### 2. 바둑판 읽기 — `core/BoardReader.java`
- 두 모서리 좌표로 모든 교차점 위치를 계산합니다.
- 교차점 주변을 **대각선 방향으로만** 36곳 샘플링합니다. 가로/세로 선과 화점을 피하고, 돌 위의 "마지막 수" 표시는 **중앙값**으로 무시합니다.
- **칸 한가운데**(선이 지나지 않는 곳)의 색을 바둑판 색으로 삼아 비교합니다.
  - 판보다 확실히 어두우면 → 흑돌
  - 판보다 밝고 색이 거의 없으면 → 백돌
  - 그 외 → 빈칸
- 추천 고리는 샘플링 영역(간격의 30%)보다 바깥에만 그려서, 고리가 돌로 잘못 읽히지 않습니다.

### 3. 수 분석 — `core/Engine.java`

| 단계 | 내용 |
|---|---|
| 모양 표 (`Shape`) | 한 줄에서 "여기 두면 어떤 모양?"을 3¹⁰ = 59,049가지 모두 미리 계산 (5목·열린4·4·열린3·3·열린2…). 렌주 흑용(정확히 5목) 표는 따로 |
| 증분 갱신 (`Position`) | 돌을 놓거나 무를 때 그 돌을 지나는 4줄의 주변 칸만 다시 계산 |
| 즉시 판단 | 5목 완성, 상대 4 막기 |
| VCF | 4를 연달아 두어 이기는 수순을 찾음 (나 / 상대 모두). 상대 VCF를 못 막는 수는 "불리"로 표시 |
| 알파-베타 탐색 | negamax + PVS, **반복 심화**로 생각 시간이 다 될 때까지 1수, 2수, 3수 … 깊이 읽음 |
| 치환표 | Zobrist 해시로 이미 본 판을 기억 |
| 위협 확장 | 상대 4는 반드시 막아야 하므로 깊이를 줄이지 않고 따라감 |
| 후보 줄이기 | 상대에게 열린3/4-3/3-3 위협이 있으면 막는 수와 내 4만 검토, 아니면 점수 상위 8~24개 |
| 렌주룰 | 흑의 3-3(진짜 3인지 재귀 확인), 4-4, 장목을 금수로 판정해 추천에서 제외. 백이 4를 만들었는데 흑이 막을 자리가 금수면 백 승 |

**생각 시간에 따른 실력** (같은 PC에서 자체 대국 8판, 흑백 번갈아)

| 대결 | 결과 |
|---|---|
| 깊이 탐색 0.3초 vs 단순 점수 AI | 8승 0패 (평균 깊이 5.8) |
| 깊이 탐색 1.0초 vs 깊이 탐색 0.2초 | 6승 2패 (평균 깊이 7.5) |

### 4. 오버레이 — `OverlayUi.java`
- 추천 고리 창: 화면 전체, 터치 통과(안드로이드 12+ 규칙에 맞게 불투명도 0.8)
- 조작 패널: 끌어서 이동, 접기, 판 맞추기 / 일시정지 / 종료
- 판 맞추기 화면: 두 모서리 십자 + 격자 미리보기 + 미세 조정 버튼

## 프로젝트 구조

```
app/src/main/java/com/hmfire/omokhelper/
├── MainActivity.java      첫 화면 (설정, 권한, 시작/중지)
├── CaptureService.java    화면 캡처 → 읽기 → 분석 → 표시 반복
├── OverlayUi.java         추천 고리, 조작 패널, 판 맞추기 화면
├── ImagePixels.java       캡처 이미지를 BoardReader에 연결
├── Settings.java          설정 저장
└── core/                  (안드로이드와 무관한 순수 자바 — PC에서 테스트 가능)
    ├── Shape.java         한 줄 모양 표
    ├── Position.java      판 상태, 증분 모양 갱신, 렌주 금수, Zobrist 해시
    ├── Engine.java        VCF + 반복 심화 알파-베타 탐색, 추천 이유
    ├── Analysis.java      분석 결과
    ├── BoardReader.java   이미지에서 돌 읽기
    ├── Coords.java        좌표 표기 (예: H8)
    └── Rule.java          자유룰 / 렌주룰
app/src/test/java/com/hmfire/omokhelper/core/
├── ShapeTest.java         모양 판정
├── EngineTest.java        5목, 막기, 열린3 수비, 4-4, 렌주 금수, VCF 검증, 4초·5초 시간 제한, 취소
└── BoardReaderTest.java   가짜 게임 화면(나무/초록/밝은 판, 15/19줄, 추천 고리 포함)으로 인식 확인
```

## 직접 빌드

Android SDK가 있는 PC에서:

```bash
./gradlew testDebugUnitTest   # 테스트
./gradlew assembleRelease     # APK → app/build/outputs/apk/release/
```

GitHub에 push 하면 Actions가 테스트하고 APK를 만듭니다. `main` 브랜치면 `latest` 릴리스에도 올립니다.

> `app/omok-helper.keystore` 는 이 앱 전용 **공개 테스트 서명 키**입니다. 새 버전을 기존 앱 위에 덮어 설치할 수 있게 하려고 저장소에 넣었습니다.
> 플레이 스토어 배포처럼 서명이 중요한 곳에는 쓰지 마세요.

## 한계

- 세로 화면 기준입니다. 화면을 돌리면 처음 방향으로 돌려야 합니다. 바둑판 위치가 바뀌면 [판 맞추기]를 다시 하세요.
- 판과 돌 색이 비슷한 특이한 테마(어두운 판, 아주 밝은 회색 판 등)에서는 인식이 틀릴 수 있습니다.
- 차례는 돌 개수로 추정합니다(흑이 먼저). 개수가 맞지 않는 변형 규칙에서는 "내 돌"을 흑/백으로 정해 주세요.
